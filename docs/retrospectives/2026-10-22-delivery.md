## What worked

Small follow-up fixes connected observable defects to focused checks. The news
navigation regression was reproduced against a production static build, rather
than inferred from a working development page. Theme measurements distinguished
less drawing work from an unproven frame-rate claim. The existing release
pipeline publishes the image that passed its container checks and deploys its
immutable digest, giving an inspectable source-to-release chain.

| A healthy local container ignored SIGTERM and exited 137 after Docker's deadline | Health verification covered startup/HTTP but did not test the PID 1 shutdown lifecycle | [PR #95](https://github.com/Installity/cs4421-astro-blog/pull/95) adds an explicit draining launcher and CI exit-0 check; the local repeat exited 0 in 0.178 seconds, with a subsequent cleanup-refinement repeat at 0.209 seconds. This PR is not yet merged/deployed |
| Course-readiness claims lacked direct operations evidence | Configuration, successful checks, human review and runtime/drill outcomes can be mistaken for one another | The readiness issues split missing code from verification. No individual is blamed for these failures. The useful changes are broader
verification coverage, explicit evidence boundaries, and smaller feedback loops.
